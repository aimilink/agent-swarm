# 使用指南：接入 Hermes Agent 并组成团队

## 1. 接入前确认

按 [部署教程](deployment.md) 安装并启动控制台。服务需要与日常 Hermes 使用同一系统用户；默认 shared 模式读取该用户的 Hermes Home，显式设置 HERMES_HOME 时以该路径为准。

本项目接入的是 Hermes Profile：SOUL、技能、记忆、模型和工具配置继续由该 Profile 保存。它不会接管另一个终端中已运行的对话或复制对话上下文。Leader 会接入团队 MCP；主动修改人设、模型或工具会写回共享 Profile。

## 2. 创建团队与接入成员

1. 打开“团队管理”，点击“新建团队”。首次进入无团队时可点“创建第一个团队”。
2. 填写唯一团队标识，例如 `tech`，以及显示名称。标识为 3–42 个字符，以小写字母开头、字母或数字结尾，中间允许小写字母、数字和连字符。
3. 点击“新员工”，系统会立即读取 Hermes Profile，并在弹窗开启期间每 3 秒同步；也可点击“刷新”。选择已有 Profile，或输入新 Profile 名称。设置姓名、Leader/Worker 角色和所属团队，再点击“入职”。
4. 每团队最多一个 Leader，可以有多个 Worker；未分组成员也最多保留一个 Leader。一个 Profile 只能注册一个 Agent，一个 Agent 同时最多属于一个团队。
5. 已注册的 Agent 不需重复接入。在团队卡片中点击“查看成员”，选择 Agent 加入，或将现有成员移出。已有 Leader 的团队不会在加入列表中提供其他 Leader。
6. 在成员页检查就绪和运行状态，启动需要参与任务的 Agent。仅运行中且已就绪的 Agent 可调度。

“沿用已有 Profile 配置”适合保留该 Agent 原有模型；主动选择其他模型配置将更新 Profile。

## 3. 下发任务

在“团队概览”或“团队任务”底部任务栏：

1. 选择团队范围，然后核对旁边显示的具体接收 Agent。
2. 需要拆解、分工与验收时选择 Leader；明确的单人工作可以直接选 Worker，但其团队仍需有可调度 Leader。
3. 输入目标、交付物和验收标准，点击“创建任务”。该操作创建 Kanban 任务；后续执行由派发流程驱动，可使用“派发”或开启“自动派发”。
4. 在看板查看待执行、执行中、阻塞和已完成状态，点击任务查看详情。任务卡也可用 Enter 或空格打开。
5. Agent 请求人工输入时，在对应任务中回答；Leader 通过后续复盘判断继续派工或交付。

“全部团队”是查看和选择范围，不是向所有团队群发，也不会根据一句自然语言自动选择销售、技术等团队。真正按关键词选择团队的入口为 `POST /api/org/dispatch`。

Leader 的父任务显示完成，可能只表示本轮拆解或复盘结束；应结合 Worker 结果和 Leader 最终答复确认用户目标是否完成。

### 3.1 Agent 对话

一对一交流可从侧栏“Agent 对话”或成员卡片“对话”进入。选择 Agent，点击“新建对话”，输入消息后按 Enter 发送；Shift+Enter 换行。左侧历史对话列表可打开已有会话继续聊天，切换 Agent 会切换其历史列表。

聊天记录保存在控制台数据库；新会话不带入其他 Web 会话记录，同一 Profile 的持久记忆仍然共享。聊天直接调用 Hermes CLI，使用所选 Profile 和模型，不受团队就绪状态限制，无需启动 ACP 终端，控制台不会自动创建看板任务。使用限制、异常恢复和 API 见 [Agent 对话](AGENT-CHAT.md)。

### 3.2 A2A 对话

两个 Agent 需要直接澄清或讨论时，从侧栏进入“A2A 对话”，选择发起方和接收方后新建会话。在线且就绪的接收 Agent 会立即处理；离线消息显示为排队，并在该 Agent 启动后自动投递。回复保存到同一会话，下一轮可切换任一参与者作为发言方。

A2A 不会创建 Kanban 任务。需要正式派工、依赖跟踪、产物登记或验收时，应从项目或任务看板发起。MCP 用法、消息状态和重试规则见 [A2A 对话](A2A.md)。

### 3.3 项目资料与交付物集中管理

从“项目工作区”新建项目，填写目标与验收标准，并选择一个或多个参与团队；同一团队可参与多个项目。项目列表与首页显示团队标签，侧栏“团队参与项目”提供团队视角，详情中的“管理参与团队”可调整关联。将资料放入页面显示的项目目录。在该页面按迭代创建任务时，只能选择参与团队中的 Agent；迭代编号自动递增，父任务、Worker、复盘和续接使用同一项目目录；产物可由 Agent MCP 或页面登记。点击“刷新项目”查看关联任务、资料和交付记录。存量项目保持未关联状态并兼容原有 Agent 选择，已有任务和文件不会自动迁移。详见 [项目工作区](PROJECTS.md)。

## 4. 跨团队协作

来源 Leader 使用 `delegate_to_team` 将工作交给目标团队 Leader；目标 Leader 在自己的 board 上组织执行，来源 Leader 使用 `list_team_delegations` 查询状态与结果。团队内创建 Worker 子任务不允许直接指派其他团队 Worker。

当前跨团队能力和限制见 [多团队说明](MULTI-TEAM.md)。共享 Profile 接入与浏览器回归不代表真实模型、运行时和结果回流已经完成部署验收。

## 5. 管理与异常恢复

| 操作或现象 | 处理方式 |
|---|---|
| 编辑团队 | 卡片点“编辑”；修改名称/描述，slug 不可改。 |
| 删除团队 | 先从“查看成员”移出所有成员，再删除空团队；保留 Agent Profile。 |
| 把成员加入另一团队 | 会移动归属，不会复制 Agent；有任务执行时应先完成或处理任务，再迁移。 |
| 没有可接收任务的 Agent | 检查所选范围，先确认 Leader 已就绪且运行，再检查 Worker。 |
| 创建任务失败 | 页面显示错误并保留原输入，排除原因后重试。 |
| 提交期间继续输入 | 成功后保留新草稿，不覆盖下一条任务内容。 |
| 团队加载失败 | 在团队弹窗点击“重试”。 |
| Agent 启停失败 | 查看反馈，核对 Hermes 环境及服务端日志后重试。运行状态为 crashed 时，下次任务派发会先尝试恢复；手动停止的 Agent 不会自动启动。 |
| 同名团队 | 用 slug 辨认；成员筛选按 team_id 区分。 |
| 调队后旧任务无法继续派发 | 旧任务团队仍保留历史归属，不允许借旧任务向新团队派发。 |

成员搜索支持姓名、Profile 与角色。看板顶部团队筛选与底部团队范围同步，实时刷新保留选中范围。手机端可通过顶部菜单展开侧栏。

### 界面密度与缩放

桌面界面默认采用紧凑布局，建议将浏览器缩放恢复到 100%。顶栏为 52px、侧栏为 216px，主要间距约为原来的 80%；正文保留 14px，辅助标签为 12px，避免整体缩放导致文字过小。手机端保留较大的输入字号和点击区域。
